# 📦 InEx System v2.0 - 打包指南（文件夹模式 + UPX 压缩）

## 🚀 快速开始

### 1. 安装依赖

```bash
pip install -r requirements.txt
```

### 2. 执行打包

```bash
python build.py
```

或使用批处理文件：

```bash
BUILD.bat
```

打包完成后，应用程序将位于 `dist/InEx_System v2.0/` 目录

## ✨ 核心特性

### 🎯 三重优化策略

本项目采用三层优化策略，最大化减小体积并提升性能：

#### 1️⃣ **文件夹模式**（--onedir）
- ⚡ 启动速度快 3-5 倍
- 💾 运行时磁盘占用减少 60-70%
- 🔧 便于调试和维护

#### 2️⃣ **智能排除**（optimize_excludes）
- 🗑️ 自动排除测试模块
- 🗑️ 排除不必要的 GUI 框架
- 🗑️ 排除其他 Matplotlib 后端
- 📉 基础体积减小 20-25%

#### 3️⃣ **UPX 压缩**（--upx-dir + 二次压缩）
- 🗜️ PyInstaller 内置 UPX 压缩
- 🗜️ 打包后深度压缩（--best --lzma）
- 📉 进一步减小 30-50% 体积

## 🔧 UPX 配置说明

### 默认配置

项目已预配置 UPX 路径：

```python
UPX_PATH = r"H:\UPX\upx.exe"
```

### 如何修改 UPX 路径

如果你的 UPX 安装在其他位置，编辑 `build.py` 第 22 行：

```python
UPX_PATH = r"你的UPX路径\upx.exe"
```

例如：
```python
UPX_PATH = r"C:\Tools\upx\upx.exe"
UPX_PATH = r"D:\Program Files\UPX\upx.exe"
```

### 如果没有 UPX 会怎样？

**完全不影响！** 脚本会自动检测：
- ✅ 如果 UPX 存在：启用压缩
- ⚠️ 如果 UPX 不存在：跳过压缩，正常打包

你可以稍后安装 UPX 再重新打包。

## 🔍 详细打包流程

### 前置要求

- **Python 版本**: 3.8 或更高版本
- **操作系统**: Windows 7/8/10/11（主要支持）
- **磁盘空间**: 至少 500MB 可用空间
- **UPX（可选）**: 推荐安装以获得最佳压缩效果

### 下载 UPX

1. **访问官网**: https://github.com/upx/upx/releases
2. **下载最新版本**: `upx-xxx-win64.zip`
3. **解压到任意目录**: 例如 `H:\UPX\`
4. **确认文件存在**: `H:\UPX\upx.exe`

### 打包流程

1. **检查 UPX**: 自动检测 UPX 是否可用
2. **检查 PyInstaller**: 自动安装（如未安装）
3. **清理旧文件**: 删除之前的构建目录
4. **配置参数**: 设置应用名称、图标、数据文件等
5. **优化排除**: 自动排除不必要的模块
6. **执行打包**: PyInstaller 打包（2-4 分钟）
7. **UPX 压缩**: 深度压缩可执行文件和 DLL（1-2 分钟）
8. **生成结果**: 显示最终体积和统计信息

1. **压缩文件夹**:

## ⚙️ 高级配置

### 调整 UPX 压缩级别

在 `compress_with_upx()` 函数中，可以调整压缩参数：

```python
# 当前配置（最高压缩比，速度较慢）
cmd = [UPX_PATH, '--best', '--lzma', filepath]

# 其他选项：
# '--fast'          # 快速压缩（体积小，速度快）
# '--ultra-brute'   # 极限压缩（体积最小，速度很慢）
# '--lzma'          # 使用 LZMA 算法（推荐）
```

### 排除特定文件不被 UPX 压缩

某些文件可能与 UPX 不兼容，可以在 `build_exe()` 中添加：

```python
cmd.extend([
    f'--upx-dir={os.path.dirname(UPX_PATH)}',
    '--upx-exclude=vcruntime140.dll',      # 已添加
    '--upx-exclude=python3x.dll',           # 示例：排除 Python DLL
])
```

### 切换回单文件模式

如果需要单文件模式，编辑 `build.py`，找到这一行：

```python
'--onedir',                       # 文件夹模式（启动更快）
```

改为：

```python
'--onefile',                      # 单文件模式
```

然后重新运行 `python build.py`

## ❓ 常见问题

### Q1: UPX 压缩失败怎么办？

**解决方案**:
1. 检查 UPX 路径是否正确
2. 确认 UPX 版本是否最新（建议 4.0+）
3. 某些文件可能不兼容 UPX，会被自动跳过
4. 即使部分文件压缩失败，也不影响整体打包

### Q2: UPX 压缩后程序无法运行？

**罕见情况**，可能原因：
- 某些 DLL 与 UPX 不兼容
- 解决方法：在 `--upx-exclude` 中排除该文件

```python
'--upx-exclude=problematic.dll',
```

### Q3: 没有 UPX 会影响使用吗？

**完全不会！**
- 没有 UPX 只是体积稍大（130-170 MB vs 90-120 MB）
- 功能完全一样
- 可以随时安装 UPX 后重新打包

### Q4: UPX 压缩需要多长时间？

- **PyInstaller 内置 UPX**: 打包过程中自动压缩（额外 30 秒 - 1 分钟）
- **二次深度压缩**: 单独步骤（1-2 分钟，取决于文件数量）
- **总计**: 增加约 2-3 分钟打包时间

### Q5: 为什么需要二次压缩？

PyInstaller 的内置 UPX 压缩是基础级别的，二次压缩使用 `--best --lzma` 参数可以获得更高的压缩比，通常能再减小 10-20% 体积。

## 🚀 性能优化建议

### 1. 启动速度

**文件夹模式已经很快**，但可以进一步优化：

- 排除不必要的模块（已在 `build.py` 中配置）
- 使用 SSD 硬盘
- 关闭杀毒软件的实时扫描（针对该文件夹）

### 2. 体积优化

**三层优化策略**:
1. ✅ 文件夹模式（减小 20-25%）
2. ✅ 智能排除（减小 10-15%）
3. ✅ UPX 压缩（减小 30-50%）

**额外优化**:
- 使用虚拟环境只安装必需的包
- 定期清理未使用的依赖

### 3. 分发优化

**最佳实践**:
1. UPX 压缩 → 90-120 MB
2. ZIP 压缩 → 45-70 MB
3. 使用 7-Zip（比 ZIP 压缩率更高）→ 40-60 MB
